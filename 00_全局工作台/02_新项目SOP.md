# 新项目SOP

生效日期：2026-07-04

最近更新：2026-07-08

适用范围：以后所有在本 Workspace 中执行的项目。

## 1. 强制原则

每执行一个新项目，必须先创建项目文件夹。

项目文件夹必须使用：

```text
project-三位编号-项目名称
```

所有项目相关内容必须存放到对应项目文件夹中，不能放到电脑其它位置。

## 2. 新项目启动流程

### 第一步：确认项目名称

项目名称要短、明确、可识别。

示例：

```text
字节投流
小红书投放复盘
私域成交SOP
短视频脚本库
```

### 第二步：确认项目编号

在 `10_项目档案` 中查看已有项目编号，取最大编号加 1。

示例：

```text
已有：project-001-字节投流
新项目：project-002-小红书投放复盘
```

编号规则：

- 使用三位数字。
- 从 `001` 开始。
- 不复用旧编号。
- 不跳号，除非用户明确要求保留编号。

### 第三步：创建项目目录

每个项目必须创建以下结构：

```text
10_项目档案/
  project-编号-项目名称/
    00_项目总览.md
    01_需求与目标/
      README.md
    02_执行过程/
      README.md
    03_素材与资料/
      README.md
    04_交付物/
      README.md
    05_复盘与沉淀/
      README.md
```

### 第四步：填写项目总览

`00_项目总览.md` 至少包含：

- 项目编号
- 项目名称
- 项目文件夹
- 创建日期
- 当前状态
- 项目目标
- 资料归档规则
- 重要决策记录

### 第五步：按目录归档内容

- `01_需求与目标`：需求、目标、边界、成功标准。
- `02_执行过程`：过程记录、阶段方案、会议纪要、迭代记录。
- `03_素材与资料`：用户提供的素材、参考资料、原始文件。
- `04_交付物`：最终交付版本、可直接使用的成果。
- `05_复盘与沉淀`：项目复盘、踩坑记录、可复用方法。

### 第六步：建立长期交接文档

如果项目是长期项目、代码项目、自动化项目、产品型项目，必须建立或确认以下文档：

```text
AGENTS.md
docs/
  CODEX_HANDOFF.md
  CURRENT_TASK.md
  DECISION_LOG.md
  DEPLOYMENT_STATE.md
  PROJECT_STATE.md
  ROADMAP.md
  SAFETY_BOUNDARY.md
```

使用规则：

- `AGENTS.md`：记录 Codex 固定工作规则、项目定位、技术栈、安全红线和必读文档。
- `CODEX_HANDOFF.md`：跨会话交接入口。
- `PROJECT_STATE.md`：当前项目状态。
- `CURRENT_TASK.md`：当前任务和下一步。
- `DECISION_LOG.md`：重要产品、架构、流程决策。
- `DEPLOYMENT_STATE.md`：部署、环境、端口、数据库和运行状态。
- `ROADMAP.md`：后续路线图。
- `SAFETY_BOUNDARY.md`：禁止事项、安全边界和不能自动执行的动作。

### 第七步：建立 Git 版本基线

如果项目需要版本管理，必须确认 Git 状态：

```bash
git status --short
git remote -v
git log --oneline -5
```

新项目第一次提交建议：

```bash
git add -A
git commit -m "chore: 初始化项目基线"
```

提交前检查：

- [ ] 是否已经确认 `.gitignore`？
- [ ] 是否排除了 `.env`、真实密钥、token、cookie、authorization、数据库文件、构建产物？
- [ ] 是否查看过 `git status --short`？
- [ ] 是否查看过 `git diff --stat`？
- [ ] 提交信息是否能说明本次版本变化？
- [ ] 是否确认 `git remote -v` 的结果？

远程规则：

- `git commit` 只保存到本地 Git 仓库。
- `git push` 才会同步到 GitHub 或其它远程仓库。
- `git remote -v` 没有输出时，说明当前项目没有配置 GitHub 远程仓库。
- 未经用户明确要求，不主动创建 GitHub 仓库、不主动推送远程。

## 3. 禁止事项

1. 禁止把项目文件直接放在 Workspace 根目录。
2. 禁止把项目资料放到桌面、下载目录、临时目录或其它非项目文件夹。
3. 禁止同一个项目创建多个相似文件夹。
4. 禁止跳过 `00_项目总览.md`。
5. 禁止只在聊天里记录关键决策而不落到项目文档。
6. 禁止把本地 Git 提交描述成“已经提交到 GitHub”，除非已经成功执行 `git push`。
7. 禁止把真实 `.env`、token、cookie、authorization、密钥、数据库文件提交进 Git。
8. 禁止在已有未提交改动时不检查来源就覆盖同名文档。

## 4. 项目执行检查清单

启动项目前检查：

- [ ] 是否已经确认项目名称？
- [ ] 是否已经确认项目编号？
- [ ] 是否已经创建 `project-编号-项目名称` 文件夹？
- [ ] 是否已经创建标准目录结构？
- [ ] 是否已经填写 `00_项目总览.md`？
- [ ] 如果是长期项目，是否已经创建或确认 `AGENTS.md` 和 `docs` 交接文档？
- [ ] 如果需要版本管理，是否已经确认 Git 状态和远程状态？

执行过程中检查：

- [ ] 新增资料是否放进项目文件夹？
- [ ] 过程记录是否放进 `02_执行过程`？
- [ ] 交付物是否放进 `04_交付物`？
- [ ] 重要经验是否同步到 `05_复盘与沉淀`？
- [ ] 全局级别的坑是否同步到《全局复利与踩坑日志》？
- [ ] 代码、架构、安全边界、部署状态变化时，是否更新了 `docs` 交接文档？
- [ ] 阶段性完成后，是否需要提交一次本地 Git 版本？

收尾时检查：

- [ ] 最终交付物是否清晰归档？
- [ ] 项目总览是否更新状态？
- [ ] 是否完成项目复盘？
- [ ] 是否提炼出可复用 SOP？
- [ ] 是否需要更新全局工作台？
- [ ] 是否已经运行必要验证命令？
- [ ] 是否已经提交 Git 版本，或明确说明本次未提交？
- [ ] 如果需要远程备份，是否已经配置 remote 并执行 push？
