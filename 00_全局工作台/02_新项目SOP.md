# 新项目SOP

生效日期：2026-07-04

适用范围：以后所有在本 Workspace 中执行的项目。

## 1. 强制原则

每执行一个新项目，必须先创建项目文件夹。

项目文件夹必须使用：

```text
project-三位编号-项目名称
```

所有项目相关内容必须存放到对应项目文件夹中，不能放到电脑其它位置。

## 2. 新项目启动流程

### 第一步：确认项目名称

项目名称要短、明确、可识别。

示例：

```text
字节投流
小红书投放复盘
私域成交SOP
短视频脚本库
```

### 第二步：确认项目编号

在 `10_项目档案` 中查看已有项目编号，取最大编号加 1。

示例：

```text
已有：project-001-字节投流
新项目：project-002-小红书投放复盘
```

编号规则：

- 使用三位数字。
- 从 `001` 开始。
- 不复用旧编号。
- 不跳号，除非用户明确要求保留编号。

### 第三步：创建项目目录

每个项目必须创建以下结构：

```text
10_项目档案/
  project-编号-项目名称/
    00_项目总览.md
    01_需求与目标/
      README.md
    02_执行过程/
      README.md
    03_素材与资料/
      README.md
    04_交付物/
      README.md
    05_复盘与沉淀/
      README.md
```

### 第四步：填写项目总览

`00_项目总览.md` 至少包含：

- 项目编号
- 项目名称
- 项目文件夹
- 创建日期
- 当前状态
- 项目目标
- 资料归档规则
- 重要决策记录

### 第五步：按目录归档内容

- `01_需求与目标`：需求、目标、边界、成功标准。
- `02_执行过程`：过程记录、阶段方案、会议纪要、迭代记录。
- `03_素材与资料`：用户提供的素材、参考资料、原始文件。
- `04_交付物`：最终交付版本、可直接使用的成果。
- `05_复盘与沉淀`：项目复盘、踩坑记录、可复用方法。

## 3. 禁止事项

1. 禁止把项目文件直接放在 Workspace 根目录。
2. 禁止把项目资料放到桌面、下载目录、临时目录或其它非项目文件夹。
3. 禁止同一个项目创建多个相似文件夹。
4. 禁止跳过 `00_项目总览.md`。
5. 禁止只在聊天里记录关键决策而不落到项目文档。

## 4. 项目执行检查清单

启动项目前检查：

- [ ] 是否已经确认项目名称？
- [ ] 是否已经确认项目编号？
- [ ] 是否已经创建 `project-编号-项目名称` 文件夹？
- [ ] 是否已经创建标准目录结构？
- [ ] 是否已经填写 `00_项目总览.md`？

执行过程中检查：

- [ ] 新增资料是否放进项目文件夹？
- [ ] 过程记录是否放进 `02_执行过程`？
- [ ] 交付物是否放进 `04_交付物`？
- [ ] 重要经验是否同步到 `05_复盘与沉淀`？
- [ ] 全局级别的坑是否同步到《全局复利与踩坑日志》？

收尾时检查：

- [ ] 最终交付物是否清晰归档？
- [ ] 项目总览是否更新状态？
- [ ] 是否完成项目复盘？
- [ ] 是否提炼出可复用 SOP？
- [ ] 是否需要更新全局工作台？
