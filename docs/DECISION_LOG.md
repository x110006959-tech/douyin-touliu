# Decision Log

本文件记录影响项目方向、架构边界和安全边界的重要决策。

## 已确认决策

### 保留主体识别优先，不回退泛化投流系统

- 决策：系统继续优先识别投流主体和服务商场景，不回退成泛化投流诊断工具。
- 原因：第一阶段聚焦巨量本地推 / 本地生活 / 服务商，主体差异会影响指标解释、诊断路径和动作建议。

### 第一版只做诊断、建议、审批、复盘，不自动执行

- 决策：第一版闭环只覆盖诊断、动作建议、人工审批、人工执行记录和复盘。
- 原因：投放平台动作属于高风险操作，必须保留人工确认和人工执行边界。

### ReviewedMetric 是人工复核层，不替代 DataSnapshot / NormalizedMetric

- 决策：`ReviewedMetric` 作为人工复核层存在，不替代原始快照 `DataSnapshot` 和标准化指标 `NormalizedMetric`。
- 原因：需要同时保留原始证据、标准化结果和人工复核结果，便于审计和回溯。

### MetricKey 是标准指标口径入口

- 决策：`MetricKey` 是标准指标口径入口，`normalize` / `review-metrics` / `decision-engine` 均使用标准 key。
- 原因：统一口径可降低不同页面字段名、别名和来源差异导致的误判。

### packages/llm 降级为解释层，不生成最终动作

- 决策：`packages/llm` 只做解释层，不生成最终动作。
- 原因：最终动作需要可控、可测试、可审计的结构化规则，由确定性决策引擎承担。

### decision-engine 负责最终结构化动作建议

- 决策：`decision-engine` 负责最终结构化动作建议。
- 原因：动作建议需要稳定输入、明确阈值、人工检查项和审批护栏。

### ActionOutcome 只记录人工执行后的复盘，不触发平台动作

- 决策：`ActionOutcome` 只记录人工执行后的复盘结果，不触发任何平台动作。
- 原因：复盘是闭环记录，不应越过安全边界变成自动执行能力。

### 部署先走服务器 staging，不立即切正式域名

- 决策：部署先走服务器 staging，不立即切正式域名。
- 原因：当前需要先验证腾讯云 Ubuntu Docker 环境、网络、数据库、构建和运行稳定性；未备案时不建议把 `www.pxxis.com` 指向广州服务器。
