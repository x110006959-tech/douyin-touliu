# 复盘与沉淀

用于存放本项目复盘、踩坑记录、可复用方法、检查清单和后续优化建议。

## 2026-07-29｜已有采集数据时插件离线的恢复入口

- 任务页此前将历史快照误当作当前插件已可用，导致登录或复用计划后插件心跳尚未恢复时，用户只能看到离线提示，无法重新检测或配对。
- 现将历史数据流程与当前连接状态分离：保留校准和复核进度，同时展示重新检测、当前任务重新绑定和手动配对入口。
- 验收时需覆盖“已有历史采集数据 + 插件离线 + 恢复连接并继续用户主动采集”，并确认没有自动平台操作或历史证据改写。

## 2026-07-30｜真实数据的字段绑定不能依赖相邻数字

- 后台页面的 ROI、金额、不同周期和表格列会同时出现；能读到数字不代表知道数字属于哪个业务字段。
- 采集现已保留最小字段/表格绑定证据，并用路线、页面指纹、表头、行标识和列签名支持校准；首次未知表格结构必须逐格核完整张表，任何无效或未放行绑定都会阻断整次正式诊断。
- 后续真实页面验收必须保留字段名、数值、单位、周期和所在卡片/表头的脱敏截图；页面结构变化应重新校准，不要用邻近文本兜底。

## 2026-07-30｜精确数值链路与迁移实跑

- 后台原始显示值与规范化十进制文本现在贯穿插件、API、复核和大屏；规则执行只在共享受限边界内转为数值，ROI 一致性采用 `BigInt` 精确比例与展示精度判断。
- v034 首次空库迁移暴露 PostgreSQL 长索引名截断碰撞；已改为显式短索引名，并在临时空库完整应用 15 个 migration。
- 后续数据型项目不能只跑 Schema validate/generate；必须同时验证精确值往返、大数边界和目标数据库的完整迁移链。

## 2026-07-30｜内部精确值不能伪装成后台展示值

- 后台百分比 `4%` 适合规则计算时会规范化为精确比例 `0.04`，两者语义一致但展示形式不同。
- 若直接给 `0.04` 拼接 `%`，用户会看到错误的 `0.04%`，相当于把后台显示值缩小一百倍，会破坏人工校准信任。
- 摘要优先保留后台原样文本；校准表同时展示系统精确值，并将百分比明确标为“比例”。以后所有带单位换算的指标都应区分“后台展示文本”和“内部规范计算值”，不能通过静默补单位混用。
